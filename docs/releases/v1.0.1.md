Threadline v1.0.1 updates CI and release automation to support the Node.js 24 runtime and includes official v1.0 release notes.

## Highlights

- **Unread notification badge**: Displays an unread indicator in the workspace shell so new activity is immediately visible across configured accounts.
- **Native browser link handling**: External links in posts, threads, and notifications now open directly in your operating system's default browser instead of navigating inside the desktop webview.
- **Browser cache management**: Inspect disk cache usage and safely clear webview cache directly from Settings across Windows, macOS, and Linux.
- **CI & Release infrastructure**: Upgrades GitHub Actions workflows (`checkout`, `setup-node`, `upload-artifact`, `download-artifact`) to pinned Node 24 actions, resolving runner runtime deprecation warnings.
- **Provider stability & testing**: Expands test coverage for Mastodon notification parsing, provider feeds, external link routing, and webview cache lifecycle.

### Downloads

Choose `linux-x86_64` (AppImage or Debian package), `windows-x86_64` (EXE or MSI), or the macOS DMG for Apple Silicon (`aarch64`) or Intel (`x86_64`).

These installers are built by GitHub Actions and include SHA-256 checksums and build provenance attestations. Verify a downloaded installer with:

```bash
gh attestation verify ./YOUR_DOWNLOADED_FILE --repo Shin-Aska/Threadline \
  --signer-workflow Shin-Aska/Threadline/.github/workflows/release.yml \
  --source-ref refs/tags/v1.0.1 --deny-self-hosted-runners
```

Windows installers are not publisher-signed, and macOS builds are not Apple-notarized. OS security prompts may appear. GitHub provenance verification does not replace platform code signing.

### Current limits

Scheduling runs only while the desktop app is open. Provider availability, media limits, and remote outcomes remain provider-dependent. Packaged Bluesky browser OAuth requires a publicly hosted HTTPS client-metadata document; use app passwords when packaged OAuth is unavailable.
