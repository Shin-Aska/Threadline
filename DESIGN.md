## 2. Color and depth
CSS custom properties are the source of implementation tokens. Canvas `#0b1326`; sidebar/inset `#060e20`; panel `#131b2e`; container `#171f33`; raised `#222a3d`; high `#2d3449`. Text `#dae2fd`; secondary text `#c0c6d6`; muted `#8a91a0`. Primary `#a9c7ff`, primary action `#3a90ff`, on-primary `#003063`; Mastodon `#c1c1ff`; success `#4edea3`; error `#ffb4ab`. Dividers use white at 7%; focus uses primary. Surfaces use tonal layering and thin edges. Floating action bar uses a translucent raised surface, 24px blur, and `0 16px 32px -8px #0009` shadow.

## 3. Typography
Locally bundled Geist for content; JetBrains Mono for handles, counts, metadata. Heading 24/32 at 600; section 18/24 at 600; component 15/20 at 600; body 13/19; secondary 12/16; metadata 11/16 and 10/14. Headings track -0.02em. Fallbacks: system sans-serif and monospace. Do not load remote fonts at runtime. Editable account fields disable font ligatures so URL punctuation and credential characters remain individually legible.

## 4. Layout and spacing
Reference screen uses a 288px sidebar and a 56px top bar at a 1280px CSS viewport. Main canvas padding 12px; panel padding 12–16px; grid gutters 12px. Spacing scale: 4, 6, 8, 12, 16, 24, 32px. Radius scale 2, 4, 8px; avatars 12px; badges 4px. Composer targets form three columns; editor/preview split 7:5. At 1050px sidebar becomes a 64px icon rail, at 900px editor/preview stacks, and below 600px navigation becomes a compact top row and targets stack. Minimum width 320px. No horizontal document overflow. The action bar stays in normal flow on phones so it cannot obscure the editor.

## 5. Reusable primitives
Panel with heading and optional metadata; Lucide SVG icons; provider identity with initials and protocol color; badges with primary/secondary/success/neutral states; labeled field; primary, secondary, and ghost buttons; selectable destination tile; native radio policy cards; progress meter; status notice. Controls use semantic native elements, visible focus, enabled/disabled/selected states. Account identity always comes from DesktopApi, never reference mock identities.

## 6. Interaction and accessibility
Navigation switches between Composer and Accounts & Sync without losing the ephemeral draft. Destination tiles toggle real selected IDs. Three policy choices retain Rust semantics. Counts use graphemes and account capabilities; splitting remains Rust-owned. Browser mode is clearly identified and cannot publish or connect. Preserve explicit per-destination errors and results. Forms have persistent labels and autocomplete hints. Tab order follows reading order; focus rings are 2px; feedback uses status/alert regions. Only short opacity/transform transitions are permitted, and reduced-motion disables them. No decorative animation. Touch controls reach 44px on small screens.

## 7. Scope and fidelity adaptations
Reference defines visual structure and tokens; the README defines available product behavior. Actual accounts and authored text replace reference fiction. Unsupported media, scheduling, OAuth, search, notifications, and timeline streams must not appear as working controls. Native credential store wording remains accurate; no invented encryption, sync latency, health percentages, or parity checks. Browser preview can show unsplit draft content labeled as a draft, never impersonate the Rust preview. Responsive views extrapolate the desktop reference for usability.

## Functional workspace states
Workspace metadata comes from the native service: LIVE or DISCONNECTED; browser-only preview remains BROWSER. Production workspaces contain only user-connected accounts. Connection/removal refreshes the entire authoritative account snapshot and reconciles selected destinations. A failed workspace load offers Retry.
Disconnected accounts carry a text status and a Reconnect action that pre-fills public provider/identity details only. Publication requires a current native preview and available selected destinations. Planning, failure, retry, publishing and completed states have distinct messages; retrying a preview must not discard a publish error. Full success automatically clears the draft and keeps a persistent success summary beside Publish. Use the existing notice for per-destination results and a polite live region in the dispatch bar; pending publication disables inputs and synchronously blocks repeat submissions. Failures preserve authored content; destinations with successful or partially published posts are deselected before retrying. Feedback uses static text/check/error icons, following the stateful-button idle/loading/success/error mechanism with no new animation or dependency. Existing token styles and responsive layout remain the visual contract.

## First-account setup
A workspace with zero accounts opens a dedicated setup page before the application shell. Use the existing logo, navy canvas, heading, provider tabs, labeled fields, notice, and vault note. Center an 800px maximum-width setup region with spacing-scale padding; at phone widths use the existing single-column form. Heading: “Connect your first account”; explain that an existing Bluesky or Mastodon account is required. Reuse the account form with setup-specific heading and no empty statistics/list. No composer/navigation is presented until an account exists. Successful first connection opens the composer with an empty draft and the connected destination selected; removing the final account returns to setup. Browser preview shows the same empty setup with a clear desktop-only connection notice. Loading/error states render before setup without briefly showing composer. No new color or typography tokens.

## Image attachments
The composer includes an Images panel between text and publishing policy. Reuse panel, button, muted text, notice, and field tokens. Support up to four JPEG, PNG, or WebP images, each at most 2 MB. Each card has a contained thumbnail, filename, remove action, and a persistent Alt text label above an editable description with a 1,500-character counter. Cards stack vertically and shrink without horizontal overflow. Preview images appear in a two-column grid on the first thread post. Empty, reading, validation error, attached, publishing, success, and failure states must remain explicit. Reading files and publishing disable submission; publishing locks attachment edits. Full success clears images and text; failure preserves both. Files remain in ephemeral draft memory and upload only on Publish. Video and audio remain unsupported milestones.

## Hashtag assistance
Show a compact Hashtags region directly below the post editor while the caret is inside a hashtag. A bare # opens Mastodon trends; typing filters Mastodon completions and looks up the exact Bluesky tag. Group native buttons by selected account/provider and instance; display Mastodon observed usage over the returned days and Bluesky approximate search matches separately. Never add unlike counts or imply global reach. Use existing panel, inset surface, caption, mono metadata, spacing, radius, notice, focus, and button tokens. Results update after a short debounce; stale responses must never replace the current query. Selecting a suggestion replaces only the active hashtag, preserves surrounding text, and returns focus/caret to the editor. Native buttons support Tab/Enter; Escape dismisses without changing text; IME composition suspends lookup. Loading, no results, unavailable statistics, disconnected account, and per-provider retry states stay distinct and never block publishing. Results/credentials are not persisted; lookup sends only the active tag to selected providers. No animation or new font/color tokens.

## Contextual multi-account composer (current contract)
The user-provided September 15 reference replaces the permanent hashtag-region and target-grid layouts above. Preserve Threadline's existing navy palette, Geist/JetBrains typography, small radii and 12px gutters. Desktop has a 288px identity sidebar, a dominant 7:5 editor/protocol-preview split, and a bottom dispatch bar. Remove the composer hero, duplicate target tiles and large limit monitor. Start directly with "Create your post". The editor remains at least 240px tall with media and compact publishing-policy controls below; show the smallest selected account limit beside its grapheme count. No unsupported GIF, poll, emoji, formatting or scheduling controls from the illustrative reference.

Identity selection: all actual accounts are shown with initials, provider icons, name/handle, connection status and native checkboxes in a bounded scrolling sidebar list. Never seed reference identities into production. At tablet widths use a 220px sidebar (not a hidden identity rail); on phones use a compact, collapsible Accounts selector above the composer. Publication locks destination selection everywhere. Native account reconciliation stays authoritative.

Hashtag autocomplete: a fixed, portaled popover follows the active hashtag's measured position inside the textarea, including wrapping, scrolling and resize. It changes no document geometry. Width 360px, constrained to viewport with 8px clearance; max height 400px with its own scrollable results. Use existing panel/inset/edge tokens, 8px radius, restrained shadow; add violet #7047eb for Mastodon network accents and selected rows (text remains existing light text). Top filters All/Bluesky/Mastodon, merged tag rows with account-initial stacks (first three plus remainder), concise activity, and an active-row indicator. Max five rows initially; View more hashtag suggestions reveals all fetched results in the same bounded popover. No separate Hashtags card or heading.

Metrics are source observations, never reach: group tags case-insensitively, keep every contributing account, deduplicate Mastodon counts by normalized instance URL and Bluesky's shared search index (take the largest returned observation per source). Display approximate matches and observed uses as separately labeled values when mixed; never add incompatible units or imply distinct global posts across instances. Unavailable values remain unknown; source details expose account/instance and observation window. Backend fetches up to 20 Mastodon suggestions.

Keyboard: textarea retains focus; Up/Down move active option, Enter inserts only the active token, Escape dismisses, Tab proceeds naturally to controls. No interception during IME or modifier shortcuts. Use listbox/option semantics, active-descendant announcement, visible focus and selected states. Filters affect aggregated rows, not selected publication destinations. Outside focus/pointer dismisses without stealing focus. Loading, empty, partial provider error and retry stay within the popover; retry remains per account.

Protocol previews: one group per network with selected account count and compact identities; render identical native thread plans once. If same-protocol accounts have different actual plans, show distinct variants with their associated identities inside that protocol group rather than misrepresenting one account's result as universal. Preview updates and dispatch CTA use the same selected IDs. No selection means no preview groups and disabled Publish. Dispatch uses "Ready to publish to N accounts" / "Publish to N accounts" (singular at one).

Verification: test five identities (3 Bluesky, 2 Mastodon), duplicate-count handling, all filters, more results, arrow/Enter/Escape, caret-middle replacement, scrolling/wrapping/resize, IME, changing selections, different native plans, publish locking/success/failure, and error retry. Capture composer and accounts at 375/768/1280 plus reference-sized desktop, and popup interaction states. Responsive layout is extrapolated; real text/data, available functionality and accessibility take priority over illustrative reference copy and unsupported controls.
